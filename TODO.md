## 2. Data layer
- [x] Room entities: `Entry`, `PoolState`, `Level` enum (`data/` package).
      `Level.next()` holds the KANA→(none), N5→N4→N3→N2→N1→(none) chain for
      Part 3 to consume.
- [x] `Converters`: `Level` <-> String, `List<String>` meanings <-> String
      (joined on U+001F, a char that can't appear in an English gloss).
- [x] DAOs (`EntryDao`, `PoolStateDao`): random active entry from enabled
      levels, per-level unmastered count (for pool-complete check in Part
      3), CRUD, enable/disable a pool.
- [x] Vocab data source **corrected from the original plan**:
      Bluskyo/JLPT_Vocabulary (originally planned primary) turned out to
      have no English meanings at all, just kanji+reading — useless here.
      Switched to elzup/jlpt-word-list (MIT), which has them. See
      DESIGN.md "Vocabulary data source" for the full corrected writeup.
      `scripts/generate_vocab_assets.py` and `scripts/generate_kana_assets.py`
      generate the bundled `app/src/main/assets/vocab/*.json` (kana.json:
      142 hand-authored entries; n5–n1.json: 710/663/2077/1731/2655
      entries from elzup's CSVs, deduped/merged). Scripts are one-off, not
      run at build time — re-run manually if source data needs refreshing.
- [x] `AssetSeeder.seedIfNeeded()`: loads the bundled JSON via `org.json`
      (no new runtime dependency) if `entries` table is empty, seeds
      `PoolState` with KANA+N5 enabled.
- [x] Self-check: `AssetSeederTest` (JVM unit test) covers the JSON→Entry
      parsing. Needed `testImplementation("org.json:json:...")` since
